# Game 2048 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a fully animated, endless 2048 game with three undo credits, local resume, couple leaderboard, and idempotent milestone rewards.

**Architecture:** Use a pure-Dart engine that returns explicit movement and merge events for a stable-ID tile board. A ChangeNotifier provider coordinates engine state, animation phases, undo, local snapshots, and a Supabase repository; focused widgets render the board and result flows without owning game rules.

**Tech Stack:** Flutter/Dart, Provider, GoRouter, SharedPreferences, Supabase/PostgreSQL, `confetti`, Flutter test.

**Spec:** `docs/superpowers/specs/2026-09-17-game-2048-design.md`

## Global Constraints

- Preserve all unrelated staged and unstaged user changes; never reset or overwrite the existing dirty worktree.
- Use no external game or animation package; Flutter's built-in animation APIs and the existing `confetti` dependency are sufficient.
- Board size is exactly 4x4 and spawn probabilities are exactly 90% for `2` and 10% for `4`.
- The first 2048 tile celebrates once per run, then play continues without a tile ceiling.
- Every run starts with exactly three undo credits.
- Active-run state is local only; Supabase receives final results and milestone claims.
- Application milestones are unique per `user_id + game_type + milestone` and are awarded atomically.
- Follow the project's feature-first structure, Supabase client, Provider state management, pastel visual language, and GoRouter conventions.
- Each production behavior must be introduced by a failing test and verified green before continuing.
